## 2. Чем заменить то, что даёт AutoHotkey

| В AHK | Во FreeBASIC | Сложность |
| --- | --- | --- |
| `InputHook`, хоткеи, `#If`, хотстринги | Свой хук `WH_KEYBOARD_LL` (+ `WH_MOUSE_LL` для кликов), конечный автомат нажатий, таблица правил с условиями вместо `#If` | высокая |
| `Send`, `SendInput {Text}` | `SendInput` с `KEYEVENTF_UNICODE` для текста и скан-кодами для перенабора; свои нажатия отличать по `LLKHF_INJECTED` и `dwExtraInfo` | средняя |
| `A_CaretX`, Acc, UIA | `GetGUIThreadInfo`; `AccessibleObjectFromWindow(OBJID_CARET)` из oleacc; UIA через COM-вызовы по таблице методов (как в `GetCaretLocation.ahk`) | средняя |
| Gdip\_All | Плоский API GDI+ из `win/gdiplus.bi` | низкая |
| Gui (прозрачные окна флага) | Окна `WS_EX_LAYERED \| WS_EX_TOPMOST \| WS_EX_TOOLWINDOW \| WS_EX_NOACTIVATE` + `UpdateLayeredWindow` | низкая |
| Gui (окна настроек) | RqLcl: QFORM, QLISTVIEW, QCOMBOBOX, QCHECKBOX, QRADIOBUTTON, QTRACKBAR, QGROUPBOX, QTABCONTROL, QSTATUSBAR, QEDIT | низкая–средняя |
| Menu Tray | `Shell_NotifyIconW` + своё меню (`CreatePopupMenu`/`TrackPopupMenu`) или QPOPUPMENU | низкая |
| IniRead/IniWrite | `GetPrivateProfileStringW`/`WritePrivateProfileStringW`, те же разделы и ключи | низкая |
| Spell.ahk (NHunspell) | Те же `Hunspellx86.dll`/`Hunspellx64.dll` через `DyLibLoad`: `HunspellInit`, `HunspellSpell`, `HunspellSuggest`, `HunspellAdd` | низкая |
| SetTimer | `SetTimer` WinAPI или QTIMER | низкая |
| Реестр | WinAPI или QREGISTRY | низкая |
| ZipFile.ahk | Архив через Shell.Application или просто копия файлов в `backup\<дата>` | низкая |

## 3. Архитектура

Один процесс, один поток с циклом сообщений (его крутит RqLcl или свой `GetMessage`). Ключевое правило: обработчик хука только записывает нажатие в буфер и решает, пропустить его или поглотить. Hunspell, посылка текста, смена раскладки и перерисовка выполняются позже, по `PostMessage` в служебное окно. Если обработчик низкоуровневого хука работает дольше таймаута (`LowLevelHooksTimeout`), Windows 7 и новее молча снимает хук.

Вся работа с текстом — в `WString` и W-версиях API. RqLcl передаёт строки в CP1251 (`RqLcl/README.md`, «Как устроено»), поэтому через него идёт только интерфейс.

Модули:

| Файл | Назначение |
| --- | --- |
| `langbar.bas` | Вход: одна копия (мьютекс), чтение настроек, служебное окно, таймеры, цикл сообщений |
| `core/config.bi` | Настройки с теми же именами ключей, что у LangBarXX; папка `config` или `%APPDATA%` |
| `core/layouts.bi` | Список раскладок, текущая раскладка активного окна (включая консоль и UWP), смена через `WM_INPUTLANGCHANGEREQUEST` или имитацию клавиш |
| `core/caret.bi` | Положение каретки: GetGUIThreadInfo → Acc → UIA |
| `core/kbhook.bi` | Хуки клавиатуры и мыши, очередь событий, отсев своих нажатий |
| `core/hotkeys.bi` | Автомат одиночных/долгих/двойных нажатий модификаторов, сочетания, CapsLock, условия действия (активное окно, правила) |
| `core/inputbuf.bi` | Буфер набранного: скан-код, модификаторы, CapsLock; сброс при смене окна, клике, навигационных клавишах |
| `core/convert.bi` | Перевод текста из раскладки в раскладку (`VkKeyScanExW`, `MapVirtualKeyExW`, `ToUnicodeEx`), смена регистра, транслит |
| `core/sendtext.bi` | Перенабор и вставка текста, выделение (Shift+Left), работа с буфером обмена с сохранением всех форматов |
| `core/spell.bi` | Обёртка NHunspell, словари `dict\<код>\`, исключения `user_dict.dic` |
| `core/autocorrect.bi` | Решение «переключать ли» по буферу, запуск исправления, отмена, логи |
| `core/hotstrings.bi` | Автозамена: поиск сокращения в буфере, опции, переменные, вставка |
| `core/apprules.bi` | Правила приложений, проверка при смене активного окна (`SetWinEventHook(EVENT_SYSTEM_FOREGROUND)` вместо опроса) |
| `ui/gfx.bi` | GDI+: загрузка png, текстовые флаги, маски CapsLock/NumLock/ScrollLock, кэш картинок |
| `ui/overlay.bi` | Окна флажка, индикатора, уведомления |
| `ui/tray.bi` | Иконка и меню трея |
| `ui/cursors.bi` | Флаг на курсоре мыши, восстановление курсоров при выходе и аварийном завершении |
| `ui/dlg_*.bas` | Окна настроек на RqLcl |

## 4. Этапы

Каждый этап заканчивается работающей программой, которую можно запустить и проверить.

### Этап 0. Каркас и проверка рисков

- Репозиторий или папка, сборка `fbc` для 32 и 64 бит, ресурсы (иконка, версия, манифест DPI-aware).
- Одна копия, иконка в трее, пункт «Выход», чтение `langbarxx.ini`.
- Прототип хука клавиатуры вместе с одной формой RqLcl на настоящей Windows: хук не снимается, форма не мешает циклу сообщений. RqLcl до сих пор проверялась только под Wine, поэтому это делается первым.

Проверка: exe запускается, в трее иконка, в отладочном окне видны нажатия клавиш в любой программе.

### Этап 1. Раскладки и индикация

- Список раскладок, флажки из `flags\`, текстовые флаги и цвета.
- Иконка трея с флагом и пометками Num/Scroll/Caps.
- Флажок у каретки, индикатор, уведомление о смене раскладки.
- Смена раскладки кликом по трею, флажку и индикатору.

Проверка: в Блокноте, Chrome, Word и консоли флажок стоит у каретки и меняется вместе с раскладкой; число дескрипторов GDI и Handles в диспетчере задач не растёт за час работы.

### Этап 2. Переключение с клавиатуры

- Одиночные Shift/Ctrl с четырьмя режимами нажатия, Ctrl/Alt/Win+N, Shift+Shift, Ctrl+Ctrl, Ctrl+Shift+Shift.
- Режимы CapsLock (выключен, как Shift, переключение, исправление), NumLock по умолчанию, ScrollLock.
- Реакция на системное переключение (Alt+Shift, Ctrl+Shift, Win+Space).

Проверка: все способы переключения работают и не ломают обычные сочетания (Ctrl+C, Shift+стрелки, Alt+Tab).

### Этап 3. Ручное исправление

- Буфер ввода и его сброс.
- Pause, Shift+BS, Ctrl+CapsLock, ПКМ по флажку: последнее слово, слова по удержанию, посимвольно, выделенный текст через буфер обмена.
- Цикл раскладок и обратный цикл (долгое удержание), RCtrl/RShift + цифра или F-клавиша.
- Смена регистра (RCtrl+…), инверсия регистра, транслит, отмена повторным нажатием.

Проверка: «ршуддщ» → «hello» и обратно в Блокноте, браузере, Word, консоли; буфер обмена после операции тот же, что до неё.

Исключено из этапов 1–3 (решение Andrei, 2026-10-26): пометки Num/Scroll/Caps на значке; Shift+Shift, Ctrl+Ctrl, Ctrl+Shift+Shift; короткое и долгое нажатие; Caps Lock «как Shift» и режимы Scroll Lock; правый Ctrl/Shift + цифра или F-клавиша; отдельные команды регистра.

### Этап 4. Окна настроек на RqLcl

- Полное меню трея с отметками.
- «Раскладки и флажки» (QLISTVIEW с флажками цикла и картинками, QCOMBOBOX для клавиш), «Настройки клавиатуры» (QTRACKBAR), «Настройка флажка», «Настройка индикатора», «Правила приложений» с перетаскиванием прицела на окно, выбор цвета (`ChooseColorW`).
- Правила приложений начинают действовать.

Проверка: все настройки меняются из окон, сохраняются в ini и читаются при перезапуске; ini от LangBarXX 1.8.4 подхватывается без потерь.

### Этап 5. Автопереключение

- Загрузка словарей Hunspell, режимы «два языка» и «один язык».
- Правила из окна «Настройки автопереключения»: минимальная длина, аббревиатуры, цифры, границы слов, игнорирование после клика, Backspace и ручного переключения.
- Исключения, отмена (Ctrl+Z, Pause), звуки, журналы и статистика.

Проверка: на наборе слов из `logs\transform.log` и `undo.log` результат совпадает с LangBarXX или лучше; ввод не тормозит.

### Этап 6. Автозамена

Исключён целиком (решение Andrei, 2026-10-26).

- Сокращения с опциями (все раскладки, точное, внутри слов, регистр, раскладка после замены), символы завершения.
- Переменные, посылка сочетаний клавиш, вставка сохранённого буфера (`Clips\`).
- Окно «Автозамена» и редактор правила с предпросмотром; формат `hotstrings.ini` прежний.

Проверка: правила из существующего `hotstrings.ini` работают так же, как в LangBarXX.

### Этап 7. Остальное

- Флаг на курсоре мыши.
- Конвертер словарей, автозапуск, USB-версия, сброс и бэкап, «О программе», справка.
- Установщик: существующий `LangBarXX.iss` с заменой exe и добавлением `rqlcl32.dll`/`rqlcl64.dll`.

## 5. Что исправить по ходу переноса

Из отчёта об ошибках LangBarXX в новую версию не переносится:

- горячие клавиши окон настроек действуют только в активном окне настроек (пункт 1);
- адрес страницы браузера читается только для `%L_WebAddress%` и без посылки клавиш в чужие окна (пункт 2);
- все дескрипторы и объекты GDI/GDI+ освобождаются сразу; на каждом этапе проверка счётчиков GDI и Handles (пункты 3–5, 21);
- системные курсоры восстанавливаются на любом пути выхода, включая таймаут и ошибку (пункт 10);
- автозамены перестраиваются целиком при сохранении, удалённые правила перестают работать сразу (пункт 6);
- цикл раскладок считается по позиции в самом цикле (пункт 7);
- программа не удаляет файлы в своей папке при запуске (пункт 8);
- «Сброс» сбрасывает только `langbarxx.ini`, остальное — отдельными флажками (пункт 9);
- отмена в диалоге цвета не меняет цвет (пункт 12);
- отладочный вывод только в отладочной сборке (пункты 33, 39).

## 6. Риски

| Риск | Что делать |
| --- | --- |
| RqLcl не проверялась на настоящей Windows | Прототип на этапе 0; окна флажка и хук не зависят от RqLcl, интерфейс можно заменить на WinAPI |
| Строки RqLcl в CP1251 | Интерфейс на русском помещается. Для редактора автозамен и исключений с символами вне CP1251 нужно добавить в RqLcl передачу UTF-16 (внутри DLL и так UTF-8) или сделать эти поля на WinAPI |
| WndProc RqLcl в x64 с 32-битными wParam/lParam | Служебное окно и трей — своим классом окна через `RegisterClassExW` |
| Снятие хука по таймауту | Только лёгкая работа в обработчике; сторожевой таймер, который переустанавливает хук, если события перестали приходить |
| Окна с повышенными правами не получают ввод | Как и у LangBarXX: запуск с теми же правами или uiAccess; решить на этапе 2 |
| Антивирусы реагируют на глобальный хук и SendInput | Подпись exe, если будет нужна; проверка на VirusTotal после этапа 3 |

## 7. Вопросы, которые нужно решить до начала

1. **Где живёт код.** Новый репозиторий, папка в LangBarXX или часть unIDE. Предлагаю отдельный репозиторий, а RqLcl подключать как готовые `inc/` и DLL.
2. **Лицензия.** В папке установщика LangBarXX лежит текст LGPL-3.0 (`_Installer/LGPL-3.0.txt`), автор исходной программы — Krot66. Переписанная версия — производная работа; её лицензию стоит определить сразу.
3. **Совместимость настроек.** Предлагаю читать ini от LangBarXX 1.8.4 без изменений, чтобы переход был простой заменой exe.
4. **Что не переносить.** Кандидаты: поддержка Windows XP (в коде есть ветки для XP), USB-версия, статистика, конвертер словарей.
5. **Сборка из unIDE.** В README unIDE сборка FreeBASIC отмечена как «пока нет»; до её появления — `build.bat` с `fbc`.
