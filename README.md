# LangBarFB

LangBarFB — переключатель раскладки клавиатуры на FreeBASIC. Это перенос [LangBarXX](https://github.com/diakin/LangBarXX) с AutoHotkey v1.1. Окна сделаны на RqLcl: это классы RapidQ поверх LCL, они лежат в репозитории [unIDE](https://github.com/diakin/unIDE), ветка `mainTest`, папка `RqLcl`.

План переноса по этапам лежит в [docs/plan.md](docs/plan.md).

## Состояние: этап 0

Этап 0 проверяет основу на настоящей Windows. До сих пор RqLcl проверяли только под Wine.

Сейчас программа делает следующее:

- запускается только одной копией;
- показывает значок в области уведомлений. В меню по правой кнопке есть пункты «Показать окно» и «Выход», двойной щелчок открывает окно;
- ставит хук `WH_KEYBOARD_LL` в том же потоке, что и форма RqLcl. Каждое нажатие в любой программе попадает в список окна. Над списком выводятся число вызовов хука, среднее и наибольшее время обработчика, число потерянных событий и время с последнего нажатия;
- раз в 250 мс показывает раскладку активного окна (`GetKeyboardLayout`).

Нажатия программа не меняет и не глотает. Закрытие окна завершает программу.

Код пока не запускался. Под Linux он прошёл компилятор fbc 1.10.1 (`-target win32 -gen gas` и `-target win64 -gen gcc`, без сборки exe). Собрать и запустить его на Windows ещё нужно.

## Сборка

Для сборки нужны:

- FreeBASIC 1.10 для Windows;
- папка `RqLcl` из unIDE (ветка `mainTest`). По умолчанию она ищется в `..\unIDE\RqLcl`, другой путь задаётся переменной `RQLCL`.

```
build.bat 32        rem bin\langbar32.exe + rqlcl32.dll
build.bat 64        rem bin\langbar64.exe + rqlcl64.dll
```

Если `fbc32.exe` / `fbc64.exe` нет в PATH, задайте путь к компилятору переменной `FBC`, например `set FBC=C:\FreeBASIC\fbc64.exe`.

## Что проверить на этапе 0

1. exe запускается, значок появляется в области уведомлений, а второй запуск выдаёт сообщение «уже запущен».
2. Нажатия в Блокноте, браузере и консоли появляются в списке. Флаг «программная» стоит только у нажатий от других программ: экранной клавиатуры, AutoHotkey.
3. После часа обычной работы строка «хук стоит» не изменилась, нажатия по-прежнему приходят, а наибольшее время в обработчике меньше 1000 мкс.
4. Раскладка в верхней строке меняется вместе с раскладкой активного окна. Для консоли и окон UWP она может быть неверной: их разбор будет на этапе 1.
5. В диспетчере задач (столбцы «Объекты GDI» и «Дескрипторы») числа за время работы не растут.

## Файлы

| Файл | Что внутри |
| --- | --- |
| `src/langbar.bas` | Главная программа: одна копия, форма, таймер, цикл сообщений |
| `src/core/winapi.bi` | Объявления функций Windows (префикс `Lb`, без windows.bi) |
| `src/core/kbhook.bi` | Хук клавиатуры и кольцевой буфер нажатий |
| `src/core/layouts.bi` | Раскладка активного окна |
| `src/ui/tray.bi` | Служебное окно, значок и его меню |
| `build.bat` | Сборка 32 и 64 бит |

Исходники `.bas`, `.bi` и `.bat` хранятся в CP1251 с CRLF, так же как в unIDE (`.gitattributes`, `working-tree-encoding`). Строки при передаче в RqLcl должны быть в CP1251.
